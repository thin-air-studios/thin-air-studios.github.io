# Decisions: the airport maps (website)

The numbering continues the game repository's DECISIONS.md, which ends at 371. The next number is 372.

372. **The bulk builder after the review: the workflow's refs, the clash with the map robot, water relations, the plan's coverage, the downloads, and the batches (v34/bulk, item 59).** (a) The plan and the build jobs check out the ref they are dispatched on (`github.sha`), not `main`, so a one-region test on a branch runs that branch's scripts. The plan reads main's `osm/` (a sparse checkout), so an airport main already has is not planned; the commit job checks again before it adds a file. The one-region test is `gh workflow run maps-bulk.yml --ref v34/bulk -f regions=north-america/us/colorado -f push=false`. It has not been run on GitHub: nothing was pushed. (b) One publish path for both workflows, `tools/maps/publish.mjs`. Each try starts from origin's main (fetch, then reset to it), copies only the files main lacks (an existing map is never replaced), makes the `.json.gz` form where it is missing, checks the whole site against 900 MB (the commit job used to check `osm/` only), makes one commit and pushes. Five tries, waiting 10, 20, 30 and 40 s between them. The robot moves its new maps and its failures list into a stage first. The robot's "Start the next run" step now runs after a failed commit (`always()`), so a failed commit no longer ends the back-to-back chain until the schedule. The earlier wording "the two never write the same file" was false (both can build the same airport); the rule is now that a file main has is kept. The two workflows share no concurrency group on purpose: a queued run in the robot's group replaces a pending one (GitHub's rule for `cancel-in-progress: false`), so the bulk commit could drop a robot run. Tested on local bare repositories: a map the other side pushed first is kept and the rest land; a push that loses the race lands on the next try; the failures list is the run's own; nothing new exits 0 and pushes nothing; the size limit pushes nothing and exits 1; five refused tries push nothing and exit 1. (c) Water relations now skip the same small water as the ways (`SKIP_WATER`: ponds, moats, basins and the rest), as the Overpass query does with `["water"!~...]`. Denmark, EKCH: the committed code built 44 water rings (800 points); with this change 41 rings (732 points), the same as the Overpass map in `osm/EKCH.json`. The three rings removed are the outer ways of moat relations 174 (Stadsgraven, two rings) and 3775743 (Kastelsgraven). Colorado: KALS and KFNL each lose one ring, the outer way of pond relations 5993894 and 11356707. Otherwise the Colorado maps are unchanged: 41 of the 43 maps of the earlier proof are identical after gunzip, and the two differences are these rings. (d) Coverage. The plan tested the 30 km box (`NEAR_M`) on a 5 x 5 grid. The builder uses the half size `surroundHalfSize` gives for the layout, which is 9 to 20 km on the Colorado airports. The plan now estimates that half size from the airport's database runways (what the phone draws when there is no map), adds 2.5 km (`TOL_M`), caps the result at 30 km, and tests on a 9 x 9 grid. On the 43 Colorado airports the estimate was never more than 2.2 km under the builder's real size. The reason printed for an uncovered airport now comes from the test that failed: no extract's bounding box holds the boxes, no extract's polygon holds them, or every extract that holds them is over the size limit or of unknown size. Measured on the stand-in polygons: Colorado now plans 51 airports (the committed plan planned 43: the eight it dropped, K00C, K33V, K4V0, KDRO, KHEQ, KITR, KRYA and KTAD, each lies within 30 km of an edge of the stand-in rectangle, so its 30 km box crossed that edge). Denmark (the openstreetmap.fr polygon): the committed plan covered 9 airports and left EKCH, EKRN, EKVG and EKSB uncovered; now 11 are covered (EKRN and EKSB added), and EKCH and EKVG are not. EKCH's 11.5 km box crosses the Øresund, and the Danish polygon does not hold all of it, so the plan leaves EKCH to the robot. (e) Downloads. Each extract is checked against its `.md5`: Geofabrik's `<url>.md5`, and the mirror's `<name>.osm.pbf.md5` (the mirror names its checksum without `-latest`). A copy that fails the check is not kept, and the mirror is tried. The builds run one at a time (`max-parallel: 1`, was 2). Geofabrik's fair-use text could not be read: its download host reset curl's connections from this sandbox, and the text was not on the pages reached, so the one-at-a-time default stays until the owner has read it. Sizes come from the mirror's listing, else a HEAD request to Geofabrik (after three failures no more are asked); an extract with neither size is refused (its airports are reported uncovered, as over the size limit or of unknown size), since its disk need is not known. There is no cache across runs: the plan lists only airports that main has no map for, so a repeated dispatch downloads only the extracts that still have airports to build, and GitHub's cache (10 GB per repository) cannot hold extracts of several GB. (f) Batches. GitHub allows 256 jobs in a workflow run. The 394 extracts planned for `regions=all` (5,948 airports) do not fit in one run, and the plan used to fail. A run now takes the first 250 extracts (the largest airport counts first) and writes the rest to the plan's `rest` output; the commit job then starts a run for the rest with the same ref. (g) An id the index does not name is an error (exit 2), not an empty plan: `north-america/us/colorad0` failed the plan job. (h) The commit's attribution line follows the session's attribution reminder (the model that wrote the commit is named there). The house rule asks for another model's line and for no model names in commits; these conflict, and the lead decides. The same line is on the earlier commit, ef473fc. (i) Measured on the real Geofabrik index (fetched 20 October 2026 with the HTTP client of node, which reached the host where curl's connection was reset), with the site's current `osm/` (115 maps): 394 extracts, 5,948 airports planned of 6,163 without a map, 215 uncovered (214 in extracts over the 8 GB cap, 1 with no polygon: MMCM), 2,001 planned airports with partial peaks (their 120 km box crosses the extract's edge), and 168.9 GB to download. Most of the bytes are the large extracts: 7 extracts over 4 GB hold 38.6 GB (Canada 6.7 GB for 69 airports, DACH 6.3 GB for 4, France 5.9 GB for 62, Germany 5.9 GB for 23, us-south 4.6 GB for 513, South America 4.6 GB for 188, Russia 4.6 GB for 35); 26 extracts of 1 to 4 GB hold 52.7 GB; 361 extracts up to 1 GB hold 77.6 GB. The mirror has a copy of 138 of the 394 planned extracts (its listing is read two directory levels deep, and some names differ, e.g. `south_africa`); for the other 256 Geofabrik is the only source. The plan's rule is the one set: the smallest extract whose polygon holds the boxes. A set-cover pass that reuses extracts would lower the 168.9 GB, but it is not built. (j) The 8 GB cap is a choice: it leaves room for the extract, its filtered copy and the maps, and it has not been measured on a runner. A larger cap would cover some of the 214 airports; the owner can decide it after a disk test on a large extract. The split was checked on the same run: 250 extracts in the matrix and 144 in `rest`, no overlap, the same totals. Not done: a run on GitHub; the owner's reading of Geofabrik's fair-use text; a run of the chained dispatch; the 3.0 game reading the `.json.gz` form (this checkout's game reads the plain form only). (k) Checks run for this record. Colorado, 51 planned airports built by the same scripts the workflow runs (85 s): the four maps in `osm/` (KASE, KEGE, KDEN, KCOS) match element for element, with coordinates within 0 m, the same relation roles and member counts; the water rings are the robot's except at KDEN (86 against the reference's 87 rings, 1,425 points against 1,431) and KEGE (302 points against 304); the KDEN ring is not isolated, since the reference map is dated 8 October against a 20 October extract, and Overpass-style clipping also drops that ring. The peak counts match. Denmark, 12 airports, 129 s; EKCH's coast is 16 pieces in both (988 points in the build against 992 in the reference, not isolated). Game: the built KASE, KEGE and KCOS load in the play view with no page errors (33, 13 and 239 taxiways from the built maps; the runway-only fallback has none); the screenshots are in the scratch folder under site-out (game-build-*-play.png). The `publish.mjs` scenarios above; the plan's typo run (exit 2, no plan written); the unknown-size refusal (an index whose extract URL does not exist: its 51 airports reported uncovered, the reason as above); the workflow files parse as YAML.
